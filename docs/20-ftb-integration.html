22 · FTB Quests 集成

网络资源计入检测类任务（按任务需求精准收集）· 消耗型任务背包+网络合并提交（多候选弹选择 GUI）· XP 任务网络经验补足 · 手动检测命令 · 网络变化自动检测（可选）· 奖励领取选择 GUI（勾选部分 + 逐条去向）· 单条奖励 Shift 进网络 · 领取通知与入网标识 · 任务 tooltip 显示网络数量（完整千分位）· 统一数值格式化 · 检测到 rs_integration 时让路禁用

功能概述

  • 检测类任务计入网络资源：非消耗型物品任务扫描时，按任务需求精准收集主网络中的匹配物品（含已有存量），收集类任务自动完成/更新进度；不把整个网络全量注入 FTB 汇总。
  • 消耗型任务背包+网络合并提交：点击提交时先按原版从背包扣料，背包不足的缺口直接从主网络扣除并计入进度（不经过背包，背包满也能提交）。
  • 多候选选择提交 GUI：可提交物品种类 > 1 时（典型为标签/过滤器任务）弹出选择界面——左侧候选列表（名称 + 背包/网络可用量，已选行绿框高亮），右侧已选栏（独立分页）；支持数字键 1-9、滚轮、左右键调整，自动填充/补满/清空；悬停显示完整千分位数值；提交/取消/ESC 后返回 FTB 任务界面。单一候选保持原自动路径。
  • XP 任务网络经验补足：提交经验任务时玩家等级/经验点不足的部分，从主网络提取 XP 流体（1 点 = 20 mB）直接补给玩家，随后由 FTB 原生逻辑扣除并计入进度。
  • 流体/能量任务网络提交：FTB 原版这两类任务只能通过任务屏输入，现支持点击提交时从主网络直接扣除流体（fluid + NBT/components 精确匹配）或 FE 能量并计入进度。
  • 手动检测命令：/bdftb scan 手动触发一次 FTB 任务检测（忽略检测缓存，强制重新扫描主网络），用于网络存入物品后立即刷新任务进度。
  • 网络变化自动检测（可选）：开启 auto_detect_enable 后，订阅在线玩家主网络的存储变化——任务目标物品入网时经节流窗口合并，自动对相关玩家触发检测（无需手动命令）。
  • 奖励领取选择 GUI：奖励界面 Shift+点击"领取所有"打开——按章节/任务列出全部可领取奖励（显示提供奖励的任务），每条可勾选是否领取并切换去向（网络/背包；复合奖励按输出结果结算入网）；支持全选/全不选/全部网络/全部背包、去向汇总、悬停详情；提交后服务端逐条校验领取。
  • 单条奖励领取进网络：任务/奖励界面 Shift+点击单条奖励按钮，物品奖励直接进主网络（普通点击保持原版进背包）；选择奖励（choice）需玩家交互，保持原版。
  • 领取通知与入网标识：物品奖励被接管入网后补发 FTB 领取通知，并附加青色"奖励已收到网络：{物品} ×N"标识（仅统计实际入网数量）。
  • 统一数值格式化：util/NumberFormatUtil 提供千分位 / FTB 格式（K/M/B，最高 B）/ SI 单位（K/M/G/T/P/E）——任务 tooltip 用完整千分位，选择 GUI 用 FTB 格式，JEI 数量角标用 SI 整数（不解析内容，防止提前预览奖励结果）。
  • 任务 tooltip 网络数量：悬停物品/流体/能量任务时，提示框追加青色"{网络标识}网络：N"（完整千分位；标识优先网络自定义名，无则网络 ID）；按需查询 + 客户端缓存兜底 + 服务端订阅推送。
  • 检测频率可配置：ftb_integration.detect_cache_ticks 控制检测结果缓存时长（0 = 每次检测都重新扫描网络）。
队伍共享FTB 的任务进度/完成状态由 TeamData 按 FTB 队伍（teamId）共享——队伍中任一成员触发检测即推进全队进度，因此检测侧只需检测各自的主网络，不合并队友网络资源。
让路条件检测到 rs_integration（RI）加载时：MixinPlugin 不应用 FTB Mixin + 运行时开关返回 false，全部集成功能禁用。

工作流程

① 检测类任务（按任务需求精准收集）

过滤器任务（标签）编译匹配器

精准收集的意义网络里有数千种物品、任务只要几种时，只注入这几种，避免全量注入导致的内存与扫描开销；带 NBT / match_nbt / 标签任务均按 FTB 原生匹配语义处理。

已知限制与边界

  • 进度更新延迟：检测结果缓存 detect_cache_ticks（默认 1 秒，按网络共享）；未开启自动检测时网络变化不触发检测，需背包变化 / 登录 / /bdftb scan；开启自动检测后仍受节流窗口限制。
  • 收集种类上限：单次精准收集最多 detect_max_item_types 种；选择提交/奖励选择界面的候选上限为 128 条。
  • 选择提交为快照：界面打开期间网络/背包变化不会实时刷新；提交时服务端按实际可扣量部分提交（不会凭空产生进度）。
  • 选择提交合并语义：同一物品类型 + 组件合并为一行，提交时先扣背包、不足从网络扣，玩家不能指定仅从网络扣除。
  • choice 奖励不支持进网络：选择奖励需玩家在界面中选择子奖励（异步），网络标记无法覆盖，GUI 固定"原版"且 Shift 单条点击也走原版。
  • 复合奖励按输出结算：random/loot/all_table 仅在结算出 ItemReward 子奖励时入网；子奖励中的命令/经验等仍原版。loot/all_table 因 FTB 硬编码 exclude_from_claim_all 不参与"领取所有"列表，可用 Shift+单条领取进网络。
  • 奖励结果不可预览：奖励选择界面沿用 FTB 奖励图标（复合奖励为表/类型图标），不解析奖励表内容，防止提前预览。
  • 仅覆盖点击提交：消耗型任务的合成来源提交（craftedItem 非空）保持 FTB 原版，不从网络补料。
  • 任务屏未接管：FTB 任务屏（TaskScreen）的物品/流体/能量方块输入路径不接网络（点击提交路径已支持物品/XP/流体/能量）。
