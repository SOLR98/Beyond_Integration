### 1.1 为什么用 `gradle\home`

原来的 `D:\BI\worktrees\gradle` 目录（缓存齐全：8.8 / 8.14.5 发行包、85 个依赖组、NeoForm 运行时缓存）在本次受限会话里**不可写**（旧沙箱 ACL），因此把 `caches/modules-2`、`caches/neoformruntime`、`caches/jars-9`、`caches/forge_gradle`、`wrapper/dists` 整体复制到 `gradle\home`，之后所有构建/运行都指向它。两者内容等价；`gradle\home` 额外保存了本次补齐的 1.20.1 资源。

`gradle\home\gradle.properties` 新增：

```properties
org.gradle.java.installations.paths=D:\BI\worktrees\gradle\jdks\eclipse_adoptium-21-amd64-windows\jdk-21.0.13+9,D:\BI\worktrees\_jdk\jdk-17.0.2,D:\BI\jdk\jdk-21.0.2
org.gradle.java.installations.auto-download=false
org.gradle.vfs.watch=false
```

> 正常（非受限）环境可以直接继续用 `D:\BI\worktrees\gradle` 作为 `GRADLE_USER_HOME`，只需保证能读到 1.20.1 的 assets（见 §3）。

## 2. 逐分支改动

### 2.1 `0.8-1.21.1-neoforge`

`build.gradle`：

1. **BD 依赖 `compileOnly` → `implementation`**
   原来 `compileOnly "curse.maven:beyond-dimensions-1222890:9380015"`。开发环境里 `compileOnly` 不进运行时类路径，FML 直接报
   `Mod beyond_integration requires beyonddimensions 0.8.9 or above / Currently, beyonddimensions is not installed`。
   改为 `implementation` 后 BD 0.8.9 正常加载。
2. **哨戒机械臂 1.4.0-alpha.48 暂时移出运行时**
   CurseForge 上 1.21.1 移植只有 1.4.x，其 `mods.toml` 硬性要求 `tacz >= 1.2.0`；而公开渠道 TACZ 1.21.1 最高只有 `1.1.8-hotfix-r7`，本分支目标也是 `1.1.8-r3`。装上即
   `Mod sentrymechanicalarm requires tacz 1.2.0 or above / Currently, tacz is 1.1.8-r3`。
   BI 侧对哨戒只用 `ModList` 门控 + 反射/Mixin 字符串目标，缺该模组不影响启动；需要联动时放入与 TACZ 1.1.8 匹配的 1.3.6 jar 即可。

源码未改（工作区里原有的 85 个文件 import 修正保留，构建已通过）。

### 2.2 `1.21.1-NEOFORGE`

`build.gradle`：

1. **ModDevGradle `2.0.141` → `2.0.148`**
   2.0.141 自带的 NeoForm Runtime 在 `createMinecraftArtifacts` 的 `recompile` 阶段稳定失败：
   `ERROR Line: 1, ..net.minecraft.world.ticks.package-info...: null` → `Compilation failed`。
   换成 2.0.148（与 0.8N 一致）后该节点直接命中缓存 `REUSE`，问题消失。
2. **移除本地 `libs/` 依赖**
   - `libs/emi-1.1.24+1.21.1+neoforge.jar`：源码没有 EMI 类型引用（`EmiBdCompat` 只用 ModList/类名门控）。
   - `libs/sentrymechanicalarm-neoforge-1.21.1-1.3.6.jar`：公开渠道无 1.3.6；CF 的 1.4.x 与 TACZ 1.1.8 冲突（同上），开发运行不加载。
   - `libs/ponder-neoforge-1.0.85+mc1.21.1.jar`：源码无直接引用，且是哨戒的 jarJar 依赖。
   现在 clone 下来不再需要仓库外的 `libs/` 目录。

### 2.3 `1.20.1-forge`

`build.gradle`：

1. **JEI 15.56 本地 jar → Modrinth 坐标**
   `compileOnly files("libs/jei-1.20.1-forge-15.56.0.205.jar")` → `compileOnly fg.deobf("maven.modrinth:jei:9jqubC9n")`（与 0.8F 相同的写法，该版本已在缓存中）。`libs/` 缺失不再阻断构建。
2. **rs_integration 改为 `compileOnly`**
   `implementation fg.deobf("curse.maven:rs-integration-1630184:9115092")` 在开发环境会让整个 mod 加载失败：
   `IllegalStateException: Cannot get config value before config is loaded`（`ContainerTransferClient.registerKeyMappings`，1.5.0.5 的自身缺陷）。
   `MagnetHandler` 里有直接引用，所以保留 `compileOnly` 供编译；开发运行时不加载该模组（调用点本身有 `ModList.isLoaded("rs_integration")` + `catch (Throwable)` 守卫）。同时注释掉重复的 Modrinth 同款依赖 `maven.modrinth:vtvveeqA:E4ejDjYy`。
   正式使用请安装 1.5.2.2 版。

### 2.4 `0.8-1.20.1-forge`

`build.gradle`：

1. **rs_integration 两条依赖注释**（`curse.maven:rs-integration-1630184:9115092` 与 `maven.modrinth:vtvveeqA:E4ejDjYy`）
   原因同 §2.3。BI 侧全部是 `Class.forName` / 类名字符串软引用，缺该模组不影响启动。
2. **`runClient` 强制 Java 17**
   ```groovy
   tasks.withType(JavaExec).configureEach {
       javaLauncher = javaToolchains.launcherFor { languageVersion = JavaLanguageVersion.of(17) }
   }
   ```
   编译仍是 JDK 21 + `release 17`；但 MC 1.20.1 自带 LWJGL 3.3.1 在 Java 21 下 JNI 版本不受支持（日志里 `Unsupported JNI version detected`），运行到字体加载时崩 `Default font failed to load`。改用 Java 17 运行后正常。

### 2.5 Compixel / BD 改为导入本地 jar（仅 0.8 线）

0.7 线（`1.20.1-forge`、`1.21.1-NEOFORGE`）保持原样，不做本地 jar 化。

**0.8-1.20.1-forge（Forge 需要去混淆）**

`libs/`：

| 文件 | 用途 |
|---|---|
| `compixelui-1.20.1-forge-0.1.16.jar` | CompixelUI 本体（CF 0.1.16），`flatDir` + `fg.deobf` |
| `beyonddimensions-1.20.1-forge-0.8.9.jar` | BeyondDimensions 0.8.9，`flatDir` + `fg.deobf` |
| `CompixelUI-runtime-standard-1.2.0.jar` | Compose/AndroidX 编译期 API（compileOnly） |
| `CompixelUI-kotlin-1.0.0.jar` | Kotlin 库（compileOnly，运行时由 KFF 提供） |

`build.gradle`：

```groovy
// repositories 里已有 flatDir { dir 'libs' }
implementation fg.deobf("local:compixelui-1.20.1-forge:0.1.16")
implementation fg.deobf("local:beyonddimensions-1.20.1-forge:0.8.9")
compileOnly files("libs/CompixelUI-runtime-standard-1.2.0.jar")
compileOnly files("libs/CompixelUI-kotlin-1.0.0.jar")
```

> 关键：`fg.deobf(files(...))` **不会去混淆**（FG 会打印 “files(...) dependencies are not deobfuscated”），
> 必须走 `flatDir` 让 jar 变成模块坐标，文件名要满足 `<name>-<version>.jar`，坐标写成 `local:<name>:<version>`。

**0.8-1.21.1-neoforge（Neo 不需要去混淆）**

`libs/`：

| 文件 | 用途 |
|---|---|
| `CompixelUI-0.1.18-1.21.1-neoforge.jar` | CompixelUI 本体 |
| `CompixelUI-runtime-standard-1.2.0.jar` | Compose/AndroidX（Neo 版 jar 不带 jarJar，编译+运行都需要） |
| `CompixelUI-kotlin-1.0.0.jar` | Kotlin 库（compileOnly） |
| `BeyondDimensions-0.8.9-1.21.1-neoforge.jar` | BeyondDimensions 0.8.9 |

`build.gradle`：

```groovy
implementation files("libs/BeyondDimensions-0.8.9-1.21.1-neoforge.jar")
implementation files("libs/CompixelUI-0.1.18-1.21.1-neoforge.jar")
implementation files("libs/CompixelUI-runtime-standard-1.2.0.jar")
compileOnly files("libs/CompixelUI-kotlin-1.0.0.jar")
```

验证：两支 `build` 通过；`runClient` 日志出现 `mod/compixel`、`mod/beyonddimensions`、`Beyond Dimensions initialized (client)`，并正常到主菜单（见 `_net/run-0.8N-libs.log`、`_net/run-0.8F-libs.log`）。

> `libs/` 在 0.8 两支的 `.gitignore` 里。要让 jar 进版本库需 `git add -f libs/*.jar`，或把忽略规则改成白名单。

### 2.6 每个分支新增 `mods/` 批量导入目录

四个分支根目录都新增了 `mods/`（含 `README.md`）。把任意 mod jar 丢进去即可，无需改
`build.gradle`：

```groovy
// Neo 分支（官方映射，直接可用）
implementation fileTree(dir: 'mods', include: ['*.jar'])

// Forge 分支（SRG 名，作为运行期 mod 直接可用；代码里要 import 其中类时见下）
implementation fileTree(dir: 'mods', include: ['*.jar'])
```

| 分支 | 目录 | 备注 |
|---|---|---|
| `0.8-1.21.1-neoforge` | `mods/` | Neo，官方映射，编译+运行均可 |
| `1.21.1-NEOFORGE` | `mods/` | 同上 |
| `0.8-1.20.1-forge` | `mods/` | 运行期直接可用；`repositories` 已加 `flatDir { dirs 'libs','mods' }` |
| `1.20.1-forge` | `mods/` | 同上（本次给该分支补了 `flatDir`） |

Forge 分支的 jar 是 SRG 名：只作为运行期 mod 加载时不用去混淆；如果**代码里要直接引用**其中类，
把 jar 命名成 `<name>-<version>.jar`，然后改用：

```groovy
implementation fg.deobf("mods:<name>:<version>")
```

## 3. 网络不稳的处理（关键）

本次会话的外网经本地代理转发，`resources.download.minecraft.net` 单连接只有 ~50 KB/s 且大文件经常被中断；PowerShell/.NET 的 TLS 也不可用（`Invoke-WebRequest` 全部 “基础连接已经关闭”）。处理方式：

1. **依赖缓存整体复用**：不重新解析/下载 CurseMaven、Modrinth、NeoForge、Forge 依赖，改用已缓存内容（复制到可写的 `gradle\home`）。
2. **资源文件改用 Node 下载器**（Node 自带 OpenSSL，绕过本机 schannel 问题）：
   - `_net/fetch-assets.mjs`：按官方 `5.json` 并行补齐缺失对象（本次补齐 3,533 个）。
   - `_net/repair-assets.mjs`：按 `size + SHA1` 校验全部 3,600 个对象，删除坏文件后重下（本次查出并修复 71 个，含致命项 `minecraft/font/unifont.zip` 被截断）。
   - 失败的两支：`unifont.zip` 截断会让客户端在 `Default font failed to load` 崩溃，这是 0.8F/1.20.1F 最初跑不起来的主因。
3. **最终状态**：3,600 个对象全部校验通过（`完整 3600，损坏/缺失 0`）。中途剩余的最后 3 首大音乐文件（14–18 MB）用 `_net/resume-assets.mjs`（HTTP Range 断点续传）补齐。若以后缓存损坏，可重跑 `repair-assets.mjs` 校验+修复。

## 4. 复现命令

```powershell
$env:GRADLE_USER_HOME = 'D:\BI\worktrees\gradle\home'

# —— NeoForge 1.21.1 两支 ——
$env:JAVA_HOME = 'D:\BI\worktrees\gradle\jdks\eclipse_adoptium-21-amd64-windows\jdk-21.0.13+9'
cd D:\BI\worktrees\0.8-1.21.1-neoforge ; .\gradlew.bat build
cd D:\BI\worktrees\1.21.1-NEOFORGE      ; .\gradlew.bat build

# —— Forge 1.20.1 两支（运行必须 Java 17）——
$env:JAVA_HOME = 'D:\BI\worktrees\_jdk\jdk-17.0.2'
cd D:\BI\worktrees\0.8-1.20.1-forge ; .\gradlew.bat build
cd D:\BI\worktrees\1.20.1-forge     ; .\gradlew.bat build

# —— 运行客户端（四个都一样）——
$env:JAVA_TOOL_OPTIONS = '-Dskiko.data.path=D:\BI\worktrees\_skiko'   # 受限环境才需要
cd D:\BI\worktrees\<分支>
.\gradlew.bat runClient -x downloadAssets   # 资源已校验过；跳过下载任务避免被慢网拖住
```

也可以直接用 `build-all.ps1`（同目录，已实测 4/4 通过）：

```powershell
# 若提示“禁止运行脚本”，用这条：
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-all.ps1

.\build-all.ps1                       # 四个分支依次 build
.\build-all.ps1 -RunClient            # 四个分支依次 runClient
.\build-all.ps1 -Only 0.8-1.20.1-forge  # 只跑一支
```

脚本要点：按分支切换 `JAVA_HOME`（Neo→21.0.13，Forge→17.0.2）、固定 `GRADLE_USER_HOME=gradle\home`、`-p <工程目录>` 避免 PowerShell 5.1 原生子进程工作目录不同步、`--no-daemon` 避免 daemon 继承句柄导致后台作业不结束、`runClient` 加 `-x downloadAssets` 跳过慢网下载。每个分支的完整日志写到该分支根目录的 `build-all.log`。

> Gradle 8.14.5 的 `--no-problems-report` 只在沙箱里需要（旧的 `build/reports/problems/problems-report.html` 不可覆盖）；正常环境不用加。
> 1.20.1 的 assets 在 `gradle\home\caches\forge_gradle\assets`（ForgeGradle 也会自动去 `%USERPROFILE%\.minecraft\assets` 找同名对象）。
