03 · TACZ 网络供弹与装填

TACZ 枪械从网络自动取弹、弹药盒入网拆箱、创造弹药映射、换弹流程接管、查询缓存化

功能概述

TACZ（Timeless and Classics Zero）的弹药体系与 SW 不同：子弹按 ResourceLocation 弹药 ID 数据驱动。本模组实现：

  • 弹药盒入网自动拆箱——TACZ 弹药盒/子弹入网时，弹药量按弹药 ID 计入网络虚拟计数，空盒留存物理存储
  • 射击/装填从网络取弹——背包弹药不足时自动从网络提取对应弹药 ID 的子弹
  • 创造弹药箱映射——TACZ 创造/全类型创造弹药箱入网后按弹药 ID（或 *）计数，该网络对应弹药视为无限
  • 换弹流程接管——直读背包型枪械在 TACZ 原版中无法换弹，本模组接管两端换弹入口使其可以装填
  • HUD 显示网络弹药量——枪械 HUD 独立显示网络名与网络弹药存量
  • 热路径缓存化——射击/装填/判定/HUD 全部 O(1) 读查询缓存，仅首次创建做一次全量扫描
  • Tacz-Unidict 兼容——通用弹药枪动态弹药解析（TOML/JSON + 枪 NBT），$ 物品弹药同样走网络查询/扣除
与 SW 虚拟弹药的区别TACZ 侧不把弹药折算为 5 种固定类型，而是按 TACZ 的弹药 ID（ResourceLocation 字符串）逐类型计数，并单独持久化「创造弹药类型计数」。

Tacz-Unidict（TUD）兼容

TUD（modid: tacz_unidict）通用弹药枪的当前弹药由 TOML 类型映射 / gun_data JSON + 枪 NBT TudCurrentAmmo 动态决定，TACZ 原版静态路径无法解析。本模组经 compat/tud/TudAmmoCompat 调用 AmmoManager.getAmmo(枪) 动态解析；未安装 TUD、白名单枪或无数据时回退原版路径。

  • 动态弹药对齐——切换弹药后，网络查询/扣弹/创造箱判定/HUD 快照键自动跟随当前弹药 ID
  • $ 物品弹药支持——普通物品以物品注册名作为弹药 ID，与 TACZ 弹药共用同一套 BD 存储键查询/扣除（1 物品 = 1 发）；HUD 快照按注册名计入
  • Mixin 顺序——AbstractGunItemMixin priority=100（低于 TUD 默认 1000），保证 TUD 先执行、本模组读取其返回值作网络补弹基线，避免 $ 场景吞弹
客户端数据TOML 类型映射（COMMON 配置）双端可用；gun_data JSON 为本地配置（不随网络同步），客户端配置缺失时回退原版路径，可能出现 HUD 与实际扣弹不一致。

设计说明TACZ 原版对直读背包枪在换弹入口直接 return（不发包、不进动画），本模组恰好在「原逻辑放行路径」之外接管：直读枪由 Mixin 走完整换弹流程，弹匣枪保持原逻辑。接管代码复刻了 TACZ 1.1.8 的流程（事件→发包→状态→startReload）。
版本风险接管逻辑与 TACZ 内部实现强耦合（@Shadow 字段、事件顺序），TACZ 大版本更新后需回归验证。
