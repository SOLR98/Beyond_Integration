10 · 物品黑名单与插入拦截链

BD 网络插入前置拦截体系：黑名单 / 附魔分离 / 弹药折算 四处理器链

功能概述

Beyond Dimensions 的 UnifiedStorage.insert() 在真正写入前会走一条前置拦截链（UnifiedStorageBeforeInsertHandler）。本模组在 commonSetup 按模组加载情况注册 4 个处理器：

处理器加载条件行为
ItemBlacklistHandler始终黑名单物品拒绝入网
EnchantmentBookSeparatorHandler始终附魔书分离（见文档 05）
AmmoBoxExtractHandlertacz 已加载TACZ 弹药盒拆箱（见文档 14）
SuperbAmmoInsertHandlersuperbwarfare 已加载SW 弹药折算（见文档 13）
设计要点拦截链是 BD 官方扩展点（不是 Mixin），天然解耦；每个处理器返回 BeforeInsertHandlerReturnInfo(KeyAmount beforeInsert, boolean cancel)，cancel=true 时吞掉本次插入（或替换为折算后的内容）。

拦截链执行流程

BD 内部UnifiedStorage.insert(key, amount)
服务端onBeforeInsert()按注册顺序遍历处理器链
① 黑名单item id 匹配配置列表？
命中 → cancel=true
拒绝入网（物品被吞）
② 附魔分离开启且物品是多附魔书？
是 → 拆书 + 扣费（或保护标记跳过）
③ TACZ 弹药盒（tacz）→ 折算 + 空盒放行
④ SW 弹药（superbwarfare）→ 折算 + 吞掉
放行 / 替换后入库（或无处理器命中 → 原样入库）

黑名单功能细节

匹配逻辑按物品注册 ID（namespace:path）比对配置列表
命中？
命中返回 cancel → 物品不入网络
未命中放行（含 null key / 空栈 / 功能未启用等全部防御分支）
已知边界配置条目只在判空时 trim，未 trim 的比较可能导致尾空格/大小写不匹配的条目失效（建议配置时确保无空格）。

注册方式（主类 commonSetup）

UnifiedStorageBeforeInsertHandler.addHandler(blacklistHandler);   // 始终
UnifiedStorageBeforeInsertHandler.addHandler(enchantSeparator);   // 始终
if (ModList.get().isLoaded("tacz"))           addHandler(ammoBoxExtract);
if (ModList.get().isLoaded("superbwarfare"))  addHandler(superbAmmoInsert);
NeoForge 差异处理器分别位于 handler/ItemBlacklistHandler、handler/EnchantmentBookSeparatorHandler、handler/AmmoBoxExtractHandler、handler/SuperbAmmoInsertHandler，主类注册逻辑一致。

配置项（blacklist 分区）

配置默认说明
enablefalse黑名单功能开关
items["minecraft:barrier","minecraft:command_block"]禁止入网的物品 ID 列表

物品保护标记（相关机制）

客户端GUI 内 Ctrl+右键物品槽位ItemProtectExtension
C2SProtectItemPacket（NeoForge: ProtectItemPayload）
写入 NBT 标记beyond_integration:protect_sep
附魔分离跳过该物品（tooltip 显示 protected 绿字）
