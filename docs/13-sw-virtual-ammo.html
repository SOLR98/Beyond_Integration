02 · SW 虚拟弹药系统（Superb Warfare）

弹药入网折算为虚拟计数、射击从网络扣弹、查询缓存 + 差值推送、扣弹即时更新 HUD

功能概述

Superb Warfare（SW）的弹药（散装弹药 / 弹药盒 / 弹药箱）存入网络后不进入物理存储，而是折算为 5 种「虚拟弹药」计数（HandgunAmmo / RifleAmmo / ShotgunAmmo / SniperAmmo / HeavyAmmo）持久化保存。玩家 / 载具 / 女仆射击时优先从已绑定网络扣虚拟弹药。SW 创造弹药箱入网后标记为 __infinite__，该网络弹药视为无限。服务端按轮询周期扫描网络弹药并差分推送给客户端，HUD 显示网络名与「网络弹药量 / ∞」。

设计要点服务端为最终权威：所有消耗 / 提取均服务端校验，客户端只做展示缓存，不存在「客户端自报弹药」通道。

0.6.x 行为① 网络弹药寻找范围限制为仅玩家主网络（不再遍历其他网络兜底）；② 扣弹成功后立即推送弹药快照（利用 extract 返回值），HUD 不等 10 tick 轮询即可更新。
已知边界① 部分弹药类型存在整除截断：网络剩余不足一发所需时仍会扣减但记 0 发（弹药损耗，量小）；② 差值推送以扣弹玩家为主，同网络其他玩家的 HUD 快照可能停留在旧值直到触发全量刷新。

弹药提取流程（从网络取真实弹药）

客户端请求提取RequestSuperbAmmoExtractPacket(ammoType, count)
服务端取玩家主网络DimensionsNet.getPrimaryNetFromPlayer
ammoType == "__infinite__" → 直接拒绝
虚拟弹药检查先按 serializationName 找 Ammo 定义（找不到直接返回）
普通弹药min(current, count) 扣减 → 生成对应弹药物品给玩家
网络标记 ∞count 直接作为提取量（不扣虚拟计数）
安全边界（仍待修复）无限弹药时 count 仍来自客户端 long 且无上限——恶意客户端可发送超大值造成服务端卡死/实体洪水。已在 0.6.x 禁止直接提取 __infinite__ 键，但未对具体弹药类型的无限场景封顶。
