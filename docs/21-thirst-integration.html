27 · 口渴（Thirst）集成

Thirst（was Taken / was Reclaimed）联动 · 网络喂食器补水档位 · 纯净水系列流体（仅网络注册）· 网络熔炉按标记执行 Thirst 熔炼提纯（可配熔炼速度）· 机械动力（Create）灌装配方 + 沙滤提纯 · 双分支同步

功能概述

为 Beyond Dimensions 的网络喂食器（beyonddimensions:net_feeder_item）增加口渴补水能力，并注册一组可在网络中存储的纯净水系列流体，配合网络熔炉把水逐步"烧"成更高纯度。

  • 补水档位：与 BD 喂食档位同款语义（作用于口渴/水饱和），在喂食器界面新增一个右侧按钮。
  • 只使用标记槽内容：喂食/补水都只消耗喂食器 36 个标记槽中标记过的物品/流体。
  • 饥饿与口渴相互独立：到饥饿档按原逻辑喂食物；到口渴档从标记槽补水；满足其一即触发。
  • 纯净水系列流体：4 档纯度，仅注册流体本体（无方块、无桶），世界中不可放置，只作为网络存储/显示条目。
  • 网络熔炉提纯：按标记槽自动组装水瓶/水桶并执行 Thirst 熔炼配方提纯，产物按收纳回网络（可配熔炼速度）。
  • JEI：提纯经 JEI 原版熔炼分类展示（原自研流体熔炼分类已移除）。
可选依赖：本集成仅在存在口渴模组时启用；未安装时喂食器完全维持 BD 原逻辑，且不显示补水按钮。
口渴后端兼容（运行时按加载选择，经 ThirstBridge 统一）：优先 Thirst was Reclaimed（thirst，主值 thirst / 副值 quenched / 0–3 纯度 + 水纯度效果）；否则用 Legendary Survival Overhaul（legendarysurvivaloverhaul，主值 hydration / 副值 saturation，纯度映射为 HydrationEnum：纯净→PURIFIED、其余→NORMAL，补水直接操作其 capability/attachment 以绕过"满水不加"；1.20.1 Capability、1.21.1 Attachment）。
双版本 Thirst（仅 1.20.1-FORGE）：同时兼容新版「Thirst was Reclaimed」(cn.mlus.thirst) 与旧版「Thirst was Taken」(dev.ghen.thirst)。两版 modId 均为 thirst、类名/方法签名一致仅根包不同，故 ThirstBridge.get() 按“类是否存在”选择后端；旧版已作为依赖导入，ThirstCompatLegacy 直接调用其 API。

档位随 BD 的 QuickDataTag 双向同步并存于喂食器物件的设置中（键 bi_thirst_mode）。

界面按钮与角标

  • 在 BD 原有两个右侧按钮（喂食档位 / 红石控制）下方新增一个补水档位按钮，复用 BD 的 feeder_mode_* 贴图（同款语义）。
  • 两个档位按钮右下角分别叠加原版角标：喂食档位=原版饥饿图标，补水档位=原版水瓶（药水瓶物品）。角标在 renderLabels 阶段（widget 之后）绘制，确保覆盖在按钮之上。
  • 不再提供独立的"忽略饥饿"开关：饥饿与口渴为两个独立条件，满足其一即触发。
  • 回血模式按钮（原版心形图标）：开启后持续把饥饿饱和度与水饱和都补到 5 以上（并保持饱食度=20、口渴=20），以加速自然回血。
BD 若更换 UI 框架，本按钮布点/角标坐标需随 client/gui/** 一并校对。

终端取水与纯度往返

在 BD 终端界面上，对水类流体键槽位操作：

  • 正向（取出）：左键点击水类流体（本模组 4 档水 / 原版水）→ 用网络中的空桶 + 流体组合成水桶；手持单个玻璃瓶时改为产出水瓶（水药水瓶）。产出物会打上对应纯度的 Thirst 水纯度标签（未装 Thirst 时跳过）。
  • 反向（入网）：带纯度标签的水桶入网时，由 BucketSeparatorHandler 拆为对应纯度的水流体 + 空容器（水桶→空桶）。
  • 反向拆解受配置 bucket_separator_enabled 限制：关闭时不拆解，容器原样入网。
  • 仅限桶物品：bucket_separator_bucket_only（默认开）下只拆 BucketItem 子类，水瓶不再自动拆分（水瓶→水 + 玻璃瓶需将其关闭）；排除项 bucket_separator_excluded_items 中的容器（默认含森罗酒馆果汁桶）一律不拆。
  • 纯度读取 / 打标经 PurityTagger（反射调用 Thirst 的 WaterPurity），未安装 Thirst 时不加载。
纯水瓶 250 mB/瓶、水桶 1000 mB/桶；带纯度标签的水瓶在反向时按 250 mB 拆回对应水流体。

网络熔炉提纯（执行 Thirst 配方）

自 0.7.0-dev 起移除原自研「净化模式 + 流体熔炼」方案，网络熔炉改为直接执行 Thirst 的水瓶/水桶 NBT 熔炼配方：

  • 在标记槽放入“待提纯的满容器”（带 Thirst 纯度标签的水瓶/水桶）。
  • 由 NetFurnaceWaterPurifyMixin 在 workStart 末尾按标记从网络取「对应纯度的水流体 + 空容器」组装成该容器，送入输入槽。
  • 随后由 BD 原生熔炼执行 Thirst 的 minecraft:smelting 配方（脏→可接受→纯净），产物按「收纳」设置回网络。
  • 因 BD 输入槽原仅接受可熔炼物品，新增放行水容器的输入校验（NetFurnaceInputFilterWaterMixin / NetFurnaceInputStorageWaterMixin）。
  • 熔炼速度：bd_tweaks.net_furnace_smelt_speed（默认 1.0；配方耗时 = 原耗时 / 倍率）由 NetFurnaceSmeltSpeedMixin 缩放。
仅普通网络熔炉（SMELTING）；无纯度标签且无对应配方的水会被跳过，不会堵塞输入槽。

机械动力（Create）口渴兼容

Create 只把原版 minecraft:water 当"水"（FluidHelper.isWater），而 Thirst 自带的 Create 兼容也不识别 BI 的 4 档自定义水。BI 用两种方式衔接（不做"从容器倒出为 BI 流体"）：

  • 灌装（create:filling 配方）：BI 档流体 + 空瓶 / 空桶 → 对应纯度的水容器（结果带 Thirst 纯度标签）。4 档 × {水瓶 250mB / 水桶 1000mB}，位于 data/beyond_integration/recipes|recipe/create/，条件 mod_loaded create。1.20.1 结果用 nbt，1.21.1 用组件。
  • 沙滤（Sand Filter）：Thirst 的沙滤只对"原版水 + Thirst 纯度"生效，BI 的独立档位水会被原样透传；SandFilterWaterCompatMixin 在沙滤 tick 中把抽出的 BI 档水替换为高一档的 BI 水（到顶保持纯净），实现过滤提纯。
  • 带纯度标签的水容器入网时由 BucketSeparatorHandler 拆回对应 BI 档流体（并修复 1.21.1 版纯度映射因用错对象而失效的问题）。
不做 emptying（倒出）配方：从容器倒出的水仍为原版水。需同时安装 Create 与口渴模组。

JEI 显示

  • 移除原「网络熔炉流体熔炼」分类（FluidSmeltCategory）；提纯改由 Thirst 的熔炼配方经 JEI 原版熔炼分类展示。
  • 本模组其余 JEI 集成（BD 终端数量角标 / Shift 取物 / 配方转移）见文档 25、27。
