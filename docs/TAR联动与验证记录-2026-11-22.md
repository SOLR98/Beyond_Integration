## 1. TAR 功能拆解

| 子系统 | 关键类 | 作用 |
|---|---|---|
| 口径数据 | `caliber/Caliber`、`AmmoProfile`、`CaliberManager`、`CaliberDataBootstrap` | 口径表、每发弹药的伤害/穿甲/爆头/穿透/后坐/精度/初速/弹丸数/弹道系数/命中效果 |
| 逐发弹匣 | `nbt/AmmoStateStorage`、`LoadedAmmoSequence`、`NbtKeys` | 状态存 `tacz_caliber_ammo:AmmoStates`，按 `ModeKey.storageKey()` 分模式，主模式 `ModeKey.MAIN` |
| 换弹 | `reload/PouchReloadSource`、`ReloadSequenceBuilder`、`AttachmentAmmoHandler`、`UnloadHandler` | 从弹药包/背包按图案构建**逐发序列**；混装逐发生效；退弹 |
| 弹药包 | `item/AmmoPouchItem`、`menu/*`、`network/CMsgPouch*` | 独立容器 + GUI + 存/取/图案编辑 |
| 弹道/效果 | `mixin/EntityKineticBulletMixin`、`AmmoEffects`、`effect/*` | 按变体覆盖伤害/弹道，命中触发爆炸/点燃/击退/Lua 脚本 |
| 兼容 API | `compat/api/*`、`compat/runtime`、`compat/builtin/*` | 三能力 + 优先级（降序，同优先级按模块 id） |
| 网络 | `SMsgCaliberData`、`CaliberSyncSnapshot` | 服务端同步全部口径/变体参数 |

TAR 的 Mixin（`tacz_caliber_ammo.mixins.json`，`required:true` + `defaultRequire:1`）：`AbstractGunItem`、`AmmoItem`、`AmmoBoxItem`、`CommonDataManager`、`EntityKineticBullet`、`ModernKineticGunItem`、`ModernKineticGunScriptAPI` + 5 个 client（`GunHudOverlay`(priority 900)、`ClientGunTooltip`、`GunRefitScreen`、`CameraSetupEvent`、`HideAmmoModifierDiagrams`）。

## 3. 扣弹优先级：原本行为与现状

**原本（0.8F/0.8N 相同）**

| 环节 | 代码 | 行为 |
|---|---|---|
| 取 ammoId | `TaczAmmoExtractor.getAmmoId(gun)` | TUD 优先，否则 TACZ gun 数据的 `ammoId`——**只有一个 id** |
| 统计 | `countAmmoInNetworkByAmmoId` | 创造箱无限 → `MAX_VALUE`；否则精确 `ItemStackKey`（物品+NBT） |
| 扣减 | `consumeAmmoDirectly` | 只扣那一个精确键，扣不到即 0 |

即：**没有“变体/优先级”概念**；TAR 下同口径的其它变体在网络上被视作 0。

**现在（1A）**：候选顺序 = 枪自身 ammoId → 同口径其它变体（`CaliberManager.getAmmoCaliber` + `getAmmosForCaliber` 反射获取）。

**待定策略**

- A 保守：只认枪自身变体（不替玩家换弹种）
- **B 兜底（已实现）**：当前变体优先 + 同口径兜底；建议加配置 `tar_allow_caliber_fallback`（默认 true）
- C 按图案：BI 读不到 TAR 的 `PatternEntry`，只能做到“图案供完后兜底”，实际等价 B

## 4. HUD：原本行为与建议

**BI 现在**（`mixin/tacz/GunHudOverlayMixin`）：注入 TACZ `GunHudOverlay.render` 的 `@RETURN`，在右下角弹药区上方（`height-53`/`-63`，0.8 缩放、右对齐）画两行：网络名 `Net#id` + 网络弹药数（`MAX_VALUE` → `infinity`）。数据源是 `getAmmoIdClient(stack)` + `TaczAmmoCache.getCount(ammoId)`，**只统计单一变体**；不改 TACZ 自己的背包弹药数。

**TAR**：`GunHudOverlayMixin`(priority 900) 把弹药包可用数并入 TACZ 弹药计数，并显示口径/变体信息。

**问题**：同区域叠加；BI 的数字只反映单一变体（TAR 下常为 0 或偏小）；`infinity` 语义与 TAR 不同。

**建议**：BI 改为**按口径聚合**（客户端用同一套候选 id 求和），保留“网络存量”独立行；TAR 存在时整行上移（配置 `hud_offset_px`），不接管 TAR 的口径行。

| `mixin/MixinPlugin.java` | 门控：`com.tacz_caliber_ammo.*` 目标仅在 `ModList.isLoaded("tacz_caliber_ammo")` 且 `PouchReloadSource.class` 存在时应用 |

| `build.gradle` | `mods/` 仍为导入目录；**TAR 单独 `compileOnly`**（见 §6） |

**注入点**

1. `hasUsableAmmo(Player, ItemStack)` @RETURN：原本只认快捷栏弹药包；网络有该枪口径弹药时返回 `true`。
2. `supply(Player, ItemStack, int startPos, int need, ItemStack gun)` @RETURN：TAR 供弹不足时，从 BD 主网络按候选顺序扣弹、构造 `Round` 追加进返回序列；`newRound` 失败则退回网络。

**未覆盖**：玩家**完全没有弹药包**时，TAR 走“原版 + 背包差分为序列”的兜底路径，网络的弹不会被记进序列。后续方案：在 `ModernKineticGunScriptAPI.consumeAmmoFromPlayer` HEAD（优先级高于 TAR）把网络弹药预填进背包，让 TAR 的差分为序列看到真实消耗；或让 TAR 上游提供 `ReloadSource` SPI。

## 6. 编译/运行约束（重要）

`mods/` 的 `fileTree` 同时进编译与运行类路径，但 **生产（SRG）jar 在 dev 运行时必然崩**：

```
java.lang.NoSuchFieldError: f_256913_
  at com.tacz_caliber_ammo.platform.PlatformRegistries.<clinit>(PlatformRegistries.java:24)
→ Failed to create mod instance.
```

因此 `build.gradle` 拆成：

```groovy
implementation fileTree(dir: 'mods', include: ['*.jar'], exclude: ['tacz_caliber_ammo*.jar'])
compileOnly  fileTree(dir: 'mods', include: ['tacz_caliber_ammo*.jar'])
```

验证结果：`build` ✅；`runClient`（TAR 不加载）48 s 进主菜单，无崩溃。
