32 · Goety 联动（网络灵魂源）

把维度网络作为与「灵魂方舟 / 图腾」并列的第三种独立灵魂源 · 激活仪式 · 牢笼魂源（终端 / 连接宝石 / 通道替代）· 击杀沉淀 / 手动转化 · 网络复活 · HUD 第三条 · 原版仪式环境绕过 · 1.20.1-FORGE / 1.21.1-NEOFORGE

功能概述

把 Beyond Dimensions 的维度网络接成 Goety 的独立灵魂源，与「Arca（灵魂方舟，能力态）」「图腾（物品）」并列。网络魂是第三个独立容器：读取叠加、判够取“合计”原版优先（原版够则不碰网络，不足时先扣光原版、余量由网络补；吸收则先填满原版、溢出才入网）；不改变 Goety 的 SEActive/Arca 权威与复活语义。

  • 网络魂键：beyond_integration:stack_type/soul_energy（LongStackKey），与机器 FE 分离。
  • 激活门槛：网络需先经灵魂源仪式激活才能作为魂源（require_activation，默认开）。
  • 牢笼魂源：牢笼内放「便携网络终端」用其绑定网络，或放「连接宝石」用绑定玩家的主网络；也可用「维度网络通道」替代牢笼。
  • 来源：击杀沉淀（事件）与手动转化（命令）。
  • 复活：原版（Arca/图腾）无法复活时，可由网络魂兜底（可选复活落点为方舟）。
  • HUD：在原版灵魂条上方追加第三条网络灵魂条（条头为维度网络发生器贴图）。
  • 仪式环境绕过：祭坛附近满足 BD 触发方块时，原版仪式跳过环境检测。
1.20.1-FORGE / 1.21.1-NEOFORGE：1.21.1 已适配 Goety 3.2.0（NeoForge 事件/payload）；信标光柱与 OP 激活命令暂未移植。
总开关 goety_soul.enabled（默认开）。关闭时不注册任何网络取魂/沉淀逻辑，行为与未安装本模组一致。

激活门槛：灵魂源仪式

本模组专属仪式类型 beyond_integration:soul_source，成功执行时用祭坛上的便携网络终端所绑定的网络激活其灵魂源（网络级、一次性、随存档持久化，复用 NetworkAmmoData）。

检测项条件
配方type: goety:ritual、ritual_type: beyond_integration:soul_source；conditions: forge:mod_loaded goety
激活物beyonddimensions:net_terminal_item（便携网络终端）
基座材料8× space_time_stable_frame、4× echo_shard、2× cursed_cage、1× totem_of_souls、1× arca
BI 追加前置激活物是终端且已绑定网络；网络存在；执行者为该网络 owner/manager/member
祭坛运行牢笼有魂、isValid、结构（necroturgy：夜晚 + 幽匿/台阶/花盆）、魂耗、XP

完成时 SoulArkActivation.activateByRitual 激活该网络，并消耗激活物（终端）。是否强制激活由 goety_soul.require_activation 控制（关闭则所有网络默认已激活）。

牢笼魂源与优先级

对「诅咒牢笼（Cursed Cage）」，网络魂的取用来源（二选一）：

来源触发目标网络
便携网络终端牢笼内放入绑定 NetId 的终端该终端绑定的网络（无需 direct_main_net）
连接宝石（goety:soul_transfer）牢笼内放绑定某玩家的连接宝石 / 祭坛注入的施法者该玩家的主网络（需 direct_main_net）
维度网络通道替代牢笼祭坛正下方为 net_pathway通道自身绑定的网络（需 pathway_cage）

牢笼 getSouls = 原生魂 + 网络魂；decreaseSouls 原版优先：原生魂够则不碰网络，不足时先扣光原生、余量由网络补。

原版优先：全局消耗（施法/物品/仆从/巫妖治疗等）经 SEHelper 并入网络魂；判够与扣取口径一致（可用量 = 原版可用 + 网络魂），实际扣取按 Arca/图腾 → 网络 顺序。

来源：击杀沉淀 / 手动转化

来源触发开关
击杀沉淀玩家通过 Goety 获得灵魂能量（ChangeSoulEnergyEvent.Gain）时，先填满原版容器，溢出部分按比例转入网络source_kill / kill_ratio（1.0）
手动转化/bdtools network soul convert <amount> 把玩家自身 SE 转为网络魂source_manual（开）

复活参与与折扣

  • 网络复活（network_revive，默认开）：原版优先——Arca/图腾能复活时不介入；原版无法复活时若原版+网络魂合计 ≥ 原版 MaxSouls，先扣原版、余量由网络补，然后复活。落点由 network_revive_to_arca 控制：有绑定方舟则传送方舟，否则原地。
  • 网络折扣（network_discount，默认关）：开启后网络补扣的余量也受 soulDiscount（护甲等减免）影响；关闭时网络补扣部分按原价扣。

HUD：第三条网络灵魂条

  • 在原版灵魂条上方两行追加一条独立网络魂条（中间一行留给灵魂增减弹字），仅当玩家存在可用网络魂源时显示。
  • 灵魂增减弹字：网络魂 +N/-N 始终画在网络条上方；原版魂弹字在 Goety ≥ 2.5.59 由其自带 SoulChangePopup 显示，旧版则由 BI 补显示（同位置）。青色、2 秒淡出上浮、同号快速合并；登录/换网/重同步不产生假弹字。
  • 轨道/填充复用原版纹理；条头为维度网络发生器图集精灵（beyonddimensions:item/net_creater，动画由图集处理），绘制为 9×9。
  • 数值：当前值原样 long；上限值用 NumberFormatUtil.compactLarge(long)（SI 前缀 K/M/G/T/P/E）。整条水平居中，过宽时从条头右缘向右扩展。
  • 同步：服务端经 SoulHudSyncHandler 订阅主网络存储增量，仅灵魂变化时增量推送 SoulEnergySyncPacket（amount/cap 均为 long）；客户端缓存 SoulEnergyState。
HUD 上限 = min(config max_souls, 网络槽容量)（不再用接口方块的单键上限）。

原版仪式环境绕过（[goety_ritual]）

当祭坛附近满足触发方块时，跳过原版仪式的环境类检测（夜晚 / 维度 / 群系 / 高度 / 天气），保留结构方块要求。覆盖 Necroturgy / Nether / End / Sky / Geoturgy / Deep / Frost / Overgrown / Storm 等。

触发要求
维度网络通道半径内 beyonddimensions:net_pathway ≥ pathway_count（默认 1）
维度连接方块半径内 beyonddimensions:dimensional_connect_block ≥ connect_count（默认 4）
检测半径radius（默认 8）

实现：RitualRequirementsMixin 拦截 RitualRequirements.getProperStructure，仅在原版返回 false（环境未满足）时按触发方块重判，命中则返回 getStructures(...)（只忽略环境、保留结构）。

通道替代牢笼：DarkAltarBlockEntityMixin 让祭坛正下方的 net_pathway 以其绑定网络作魂源（pathway_cage，默认开）；tick 里的取/扣魂调用被重定向，牢笼为 null 时安全走网络。
