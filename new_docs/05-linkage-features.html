1. 铁魔法（Iron's Spells）网络魔力

  • 服务端：IronsManaHandler（施法时从网络扣魔力）、ManaNetRegenHandler（网络回魔）、 ManaHudSyncHandler（HUD 值同步）；3 个 Mixin 注入铁魔法施法/魔力判定。
  • 客户端：ManaState + NetManaHudOverlay/NetManaHudRenderer， 位置走 HudLayout（元素 net_mana）。
  • 协议：ManaSyncPacket（S2C 推送）。
  • 差异：1.21.1 把若干处理器拆成更多类（19 个文件），0.8.x-1.20.1 与 0.7.30-1.20.1 一致（10 个）。

2. Goety 网络灵魂源

三线共同

  • 灵魂类型/键：SoulEnergyType/SoulEnergyStackKey/SoulKeyRegistration（0.8.x 另有 SoulKeyResolver/SoulKeyMigration）。
  • 来源与消耗：NetworkSoulSource（原版优先、不足补网络）、SoulVanillaSource、SoulGainHandler（击杀沉淀）、SoulManualConvert。
  • 仪式：SoulSourceRitual/ModRitualFactories、SoulArkActivation、SoulCageContext、RitualEnvSoulCharge。
  • 复活：SoulReviveMixin + ReviveFingerprintHandler/SetHealthReviveHandler。
  • HUD：SoulEnergyGuiMixin 注入 Goety SoulEnergyGui.drawHUD，追加第三条网络魂条 + 施法进度 + 增减弹字（0.8.x 拆出 SoulHudRenderer/SoulChangePopups）。

0.8.x-1.20.1 新增：仪式结构由网络提供

  • RitualTrigger：统一前置条件（半径内 net_pathway ≥ N 且 dimensional_connect_block ≥ M）， 环境绕过与补块共用。
  • RitualNetworkStructure：原版 RitualChecker.hasBlocks 判定失败时，用网络里的方块物品补缺口； 网络清单扫描一次并缓存（网络 ID → 物品集合），数量用精确键查询；花盆拆成“花盆 + 内容物”两组取较小值。
  • RitualCheckerMixin（注入 hasBlocks RETURN）+ RitualRequirementsMixin（提示与失败清单）。
  • 配置：goety_ritual.network_structure（默认开）、structure_soul_cost（默认 100，每次结构检查最多一次）。
  • 细节见 计划项目/待办/2026-10-25-NEW_FORGE适配BD0.8.3记录.md。

4. rs_integration（RI）

  • 背景：RI 会往 BD 网络界面塞 3 个自动进食按钮并每帧覆盖坐标，与 BI 侧栏按钮重叠。
  • 0.7.30-1.20.1：compat/RsIntegrationCompat + mixin/RsIntegrationMachineHubMixin + RsIntegrationAutoEatMixin（接管安装与定位，按钮统一进 BD 左侧栏）+ client/widget/RsAutoEatButton。
  • 0.7.30-1.21.1：4 个类（RsAutoEatButton、RsIntegrationCompat、 RsAutoEatButtonGuardMixin、RsIntegrationAutoEatMixin），同样接管。
  • 0.8.x-1.20.1：已按 0.7.30 的接管方案清理——RI 相关的 5 个 Mixin 已删除：
    • 3 个配置读取安全回退（ContainerTransfer / RSidePanel / SidePanelModule）： RI 已自行修复该问题，不需要 BI 兜底；
    • 2 个失效项（RsIntegrationAutoEatReturnMixin、RsAutoEatButtonGuardMixin）： 它们依赖 0.7.30 的“接管 RI 按钮”体系（DimensionsNetGUIMixin），0.8.x 没有侧栏可接管，实际空转。
    现存的联动只有两项：JEI 集成遇 RI 整体禁用（角标/点击取物都不工作，防重复）与 MagnetHandler 入库后调用 RI 的 ExternalItemProgressBridge.enqueue（FTB 任务进度桥）。 RsIntegrationCompat 仍保留（0.7.30 的按钮接管反射助手），0.8.x 只用它的 isLoaded()。
  • 0.8.x-1.21.1：无。

6. FTB Quests：文档与代码不符（重要）

核对结论 docs/20 · FTB Quests 集成 描述的 FtbIntegrationHelper、FtbTaskNetworkScanner、FtbRewardClaimer、 Ftb*Service、11 个 Ftb*Mixin 等，在四个工程的当前源码里都不存在 （按文件名与内容检索 Ftb / ftbquests / dev.ftb 均无 BI 自有类）。
  • 目前与 FTB 有关的只有一处间接调用：feature/magnet/MagnetHandler 在物品入库后调用 rs_integration 的 com.huanghuang.rsintegration.compat.ftbquests.ExternalItemProgressBridge.enqueue(sp, stack) （软依赖，由 RI 处理 FTB 任务进度）。
  • 结论：docs/20 可能是历史版本/其他分支的实现，当前应视为未实现；若要恢复，需要按 0.7.30 的文档重新实现（并适配 0.8.x）。
  • 同一文档体系里，docs/27（终端界面增强）与 docs/28（BD 修改项）在 0.8.x 也需要重写（见 08/09 篇）。
