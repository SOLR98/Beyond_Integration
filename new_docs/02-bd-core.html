1. 插入 / 提取规则链

0.7.30 两线：拦截式

  • BD 提供 UnifiedStorageBeforeInsertHandler 前置链，BI 在链上注册规则；规则命中后自己写存储并返回 cancel（吞掉 / 替换插入）。
  • 对外扩展点：BI 的 api/IBeforeInsertExtension（其他模组可挂规则）。
  • 规则实现（两线同名）：feature/blacklist/ItemBlacklistHandler（拒绝）、 BucketSeparatorHandler（桶 → 流体 + 空容器）、 AmmoBoxExtractHandler / AmmoStorageExtractHandler（弹药箱/弹药库拆箱）、 SuperbAmmoInsertHandler（SW 弹药——0.7.30 写虚拟计数）、 EnchantmentBookSeparatorHandler（附魔书拆分）。

0.8.x-1.20.1：计划式

  • BD 0.8 改为 UnifiedStorageRules.insertMatching：规则只产出计划 （InsertPlan.reject() / convert(n).add(键, 量) / take(...) / discard().onCommit(...)），由框架事务统一提交，规则不再直接写存储。
  • 规则类同名改造；SW 改为“盒装 → 散装弹药物品”的转化规则，并新增 feature/ammo/sw/SwAmmoMigration （旧存档虚拟计数 → 物品，中文日志）。
  • 删除 api/IBeforeInsertExtension：0.8.x-1.20.1 不再向第三方暴露规则 SPI。
语义差 “拦截并自己写”和“只出计划”不能平移：前者能产生计划之外的一切副作用，后者必须用 take/add/onCommit 表达，否则会出现“规则跑了但存储没变”。

3. 存储变更订阅（核心基础设施）

  • 三线都有 core/BdSubscriptionHub：按网络订阅存储 delta（key / size / insert）， 订阅方只捕 netId，避免强引用网络对象。
  • 典型用法：药水护符（只关心护符物品增删）、SW 弹药（盒装/散装变化）、附魔书拆分后的重扫。
  • 网络销毁 / 关服时由各自功能 onNetDestroyed / clearCaches 关闭订阅。
