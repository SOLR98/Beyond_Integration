机制摘要（两条 1.20.1 工程一致）

  1. 扫描：网络内所有 charm_enabled=true 且有单条药水效果的药水护符；按效果类型去重： 保留最高等级，同等级优先“无法破坏”，其次“自身经验修补”。
  2. 门槛：无法破坏 / 自身经验修补 / 该网络已献祭解锁经验修补。
  3. 施加：每 potion_charm.interval（默认 20 tick）对主网络玩家结算； 女仆由饰品 tick 驱动；目标身上该效果剩余 ≤ refresh_lead_ticks（默认 10）才重新给予。 施加时长 = ceil(护符 NBT 里记录的 duration / 24) + refresh_lead_ticks （再生额外 + 50 >> amplifier）——即护符携带的药水时长决定网络版效果的持续时间。 注意 refresh_lead_ticks 应 ≥ interval：否则效果可能在两次结算之间过期， 出现 1~19 tick 的短暂中断（短时长药水或把间隔调大时可见）。
  4. 扣费：无法破坏免费；经验修补每次扣 potion_charm.mending_xp_cost × 20 mB 网络 XP 流体 （默认 1 XP → 20 mB），不足则本次不施加。目标已有更强/更久的同效果时 addEffect 会被拒绝， 本次不扣费；按 extract 实际取出的量记账（提取规则拒绝时不白记）。
  5. 献祭：消耗网络内一本“单条附魔=经验修补”的附魔书，持久化记录在网络附件 （NetworkAmmoData.potionCharmMending）。
  6. 性能：NetRecord 按网络缓存护符状态，core/BdSubscriptionHub 监听 delta， 只有护符相关物品增删才重扫；同一网络多玩家只处理一次。

0.8.x-1.20.1 的入口（已补齐）

已补齐 旧线的模式按钮随 BD 0.7 GUI 一起删除后，CyclePotionCharmModePacket 与 SacrificeMendingPacket 一度没有发送方。现在由新增的「网络设置」页 （client/page/NetSettingsPage.kt，注入 BD NetControlMenu）提供： 四态模式循环（仅玩家 → 仅女仆 → 两者 → 关闭）+「献祭经验修补书」按钮 + 解锁状态显示， 用的是现有两包，且与附魔分离、自动充电开关放在同一页。
  • 页面状态来自 PotionCharmState，网络 ID 取当前打开的存储/终端界面所连网络（DimensionsNetMenu.networkId()，未同步时回退主网络镜像）； 打开页面时发 RequestPotionCharmPacket 拉一次权威值。
  • 权限由服务端校验（net.isManager/isOwner），无权限会收到 message.beyond_integration.cannot_toggle_potion_charm。
  • 三个开关由服务端按菜单网络处理（handler/NetMenuResolver：有菜单取菜单网络，否则回退主网络）。未开启 bd_tweaks.primary_net_sync 且不在网络界面时页面显示“未同步网络”， 无法读取/修改（服务端按主网络处理这些开关）。

结论说明
✅ 文档新增 旧 docs 没有药水护符篇；本轮已在 docs/36 与 new_docs/07 补齐
⚠ 版本范围 1.21.1_NEOFORGE 没有该功能（无 charm 相关类；Apoth 在 1.21.1 只用于附魔台）
⚠ 入口缺口 0.8.x-1.20.1 缺 UI/命令，模式与献祭不可用（与能量充能、磁铁/漏斗档位是同一类问题）
? PotionCharmSyncPacket 在 0.8.x 仍会推送到 SuperbAmmoCache， 但没有界面读取；若补页面可直接复用这份缓存
⚠ 细节 护符记录的效果时长：apotheosis 的 PotionCharmItem 用 PotionUtils.getMobEffects 从物品 NBT 读一条带 duration 的 MobEffectInstance；网络版施加时长 = ceil(duration/24) + refresh_lead_ticks， 与原版饰品栏护符的 ceil(duration/24) + criticalDuration（5 或 210）逻辑一致， 但 BI 用可配置 refresh_lead_ticks 取代固定值。
⚠ 提示 效果不在 HUD 显示：施加用 MobEffectInstance(..., false, false)（与 Apoth 原版一致）， 无图标、无粒子；移速/攻击/回血等属性仍然生效，不要据此判断“未生效”。
? 同效果去重时是否比较时长：isBetter 只比 amplifier 与“无法破坏/Mending”， 不比 duration；同效果同等级的两个护符，选中哪个取决于扫描顺序（可能拿到时长较短的那件）。 若要“取时长最长者”，需在 isBetter 里加 duration 比较。
